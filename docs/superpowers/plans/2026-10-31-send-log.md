# Send Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Send log action on Android, desktop and CLI that uploads the device's log to the helper, which stores it for a reader on the developer's laptop to list and download with `twocan-logs`.

**Architecture:** A new package `internal/logbox` holds everything about log reports:
- the helper's on-disk store (limits, deletion, the off switch);
- an in-memory rate limiter;
- the two libp2p protocols, upload (`/twocan/logs/1.0.0`) and read (`/twocan/logs-read/1.0.0`);
- the client functions both sides call.

On top of it:
- `internal/helper` wires the store and the protocols into the helper.
- `core.Node.SendLog` gathers the log and sends it to the first helper that accepts.
- The CLI, the desktop UI and `mobile`/Android call `SendLog`.
- `cmd/twocan-logs` is the reader tool.

**Tech Stack:** Go, go-libp2p v0.51.0, protobuf (`protoc` + `protoc-gen-go v1.36.12`), Fyne (desktop), Kotlin/Compose (Android).

**Spec:** `docs/superpowers/specs/2026-10-31-send-log-design.md`

## Global Constraints

- Nothing is sent without the user's action.
- Upload protocol ID `/twocan/logs/1.0.0`; read protocol ID `/twocan/logs-read/1.0.0`.
- Frames go through `internal/wire` (64 KiB max); log chunks are at most 60 KiB.
- Store defaults: one upload at most **8 MiB**; total **256 MiB**, oldest reports deleted first; kept **7 days**, checked at startup and hourly.
- Upload limits: **2** at a time; **6 an hour per IP**, **3 an hour per peer ID**; **30 s** idle per stream.
- Gathered log: `twocan.log` plus the newest rotated file, at most the newest **16 MB** before gzip. Note: at most **500** characters.
- Off switch: the file `logs/OFF` next to the helper's key. It's checked on every upload and needs no restart.
- The logs protocols are offered only with `--log-readers <peerID>[,…]`. Pruning runs whenever the logs folder exists, even without it.
- Stored files: `<received-utc>-<code>.log.gz` and `<received-utc>-<code>.json`. Nothing the device sends becomes part of a file name.
- Code: 8 Crockford base32 characters (alphabet `0123456789ABCDEFGHJKMNPQRSTVWXYZ`) from 40 random bits, shown as `XXXX-XXXX`.
- The helper's own output (`log.Printf`) never contains peer IDs.
- `twocan-logs get` refuses to decompress more than **256 MB**.
- App copy: "Your log, including contact names and network addresses. Never your messages."

## Review Focus

1. **The phone can't reach the helper** (no helper configured, offline, wrong helper ID): Send log fails quickly with a plain reason, and Android offers Share log. *Test:* Task 5 `TestSendLogWithoutHelper`, and Task 8 `TestSendLogWithoutHelperIsFriendly`.
2. **The upload stops halfway** (the app is closed or the network drops): the helper leaves no file and frees the upload slot. *Test:* Task 3 `TestAbortedUploadLeavesNothing`.
3. **A fresh install with no log yet:** sending still works, with an empty log. *Test:* Task 5 `TestRecentWithNoLogFile`.
4. **Two uploads in the same second:** they get different codes and files. *Test:* Task 1 `TestSameSecondUploadsDoNotCollide`.
5. **The VPS disk is full, or the folder isn't writable:** the helper refuses with "storage full" and keeps running. *Test:* Task 3 `TestUnwritableStoreRefusesAsFull`.

- [ ] **Step 3: Implement `server.go` and `client.go`.**
  - **Upload handler order:**
    1. `acquire`, otherwise reply `REFUSAL_RATE_LIMITED`;
    2. read `start`;
    3. if `st.Off()`, reply `REFUSAL_OFF`;
    4. check `allow(remote IP from conn.RemoteMultiaddr(), remote peer)`;
    5. if `start.size > MaxUpload`, reply `REFUSAL_TOO_LARGE`;
    6. `Begin`, then write the chunks; extend the stream deadline by `Idle` before each frame read;
    7. on `end`, `Commit` and reply with the code.
  - **Errors:** any error from `Begin`, `Write` or `Commit` other than `ErrTooLarge` replies `REFUSAL_FULL`. Any other failure calls `Abort` and resets the stream.
  - **Read handler:** if the remote peer isn't in `Readers`, reset immediately. Otherwise serve one request per stream. `get` streams `info`, then 60 KiB chunks, then `done`.
  - **Logging:** counts and refusal reasons only, never peer IDs or addresses.
