# Twocan v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Linux desktop P2P text messenger in Go where two people on different home networks add each other by card/QR, chat directly or via a relay, and no server ever holds message data.

**Architecture:** One Go process per user: a headless `core` (identity, SQLite store, libp2p node, contacts + chat stream protocols, reconnect loop, event bus) driven by either a Fyne UI or a line-based CLI. A separate `twocan-helper` binary is the private-DHT bootstrap node, circuit relay v2 and AutoNAT server; it stores only its own key.

**Tech Stack:** Go (local toolchain 1.27), go-libp2p v0.51.0, go-libp2p-kad-dht v0.42.2, fyne.io/fyne/v2 v2.8.2, modernc.org/sqlite v1.61.0, google.golang.org/protobuf v1.36.12 (+ `protoc`, `protoc-gen-go`), github.com/google/uuid v1.6.0, github.com/skip2/go-qrcode, github.com/makiuchi-d/gozxing v0.1.1, golang.org/x/time/rate.

**Spec:** `docs/superpowers/specs/2026-10-23-twocan-design.md`

## Global Constraints

- Module path: `twocan` (no hosting decided yet).
- Linux only. No macOS/Windows work.
- No component may persist message content or contact lists anywhere except the user's own data dir. The helper persists only its key file.
- Never log message text or private keys, at any log level.
- Data dir: default `os.UserConfigDir()/twocan`, overridable with `--data-dir` on both binaries; created with mode 0700. Files inside: `identity.key` (0600), `twocan.db`.
- Stream protocol IDs: `/twocan/contact/1.0.0`, `/twocan/msg/1.0.0`. DHT protocol prefix: `/twocan`. mDNS service name: `twocan`.
- Frames: varint length-delimited protobuf, max 64 KiB (65536 bytes) per frame.
- Message text: max 16 KiB (16384 bytes) UTF-8; whitespace-only text is rejected.
- Card string format: `twocan:` + unpadded base32 (RFC 4648 std alphabet, lowercase on output, case-insensitive on input) of a `Card` protobuf, version `1`, at most 4 addrs.
- Every outbound stream is opened with `network.WithAllowLimitedConn(ctx, "twocan")` so it works over relayed (limited) connections.
- UI updates from non-UI goroutines go through `fyne.Do`.
- Relay limits on the helper: `Limit.Duration = 30*time.Minute`, `Limit.Data = 4 << 20`; other `relay.Resources` fields keep their defaults.
- Retry backoff: start 5 s, double, cap 5 min. Presence sweep of accepted contacts every 2 min.
- Every commit message ends with the line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Each milestone ends with a learning note in `docs/learning/` (plain English, ~1 page) explaining the concepts introduced, for the owner who reads along.

## Review Focus

1. **Pasted card with stray whitespace, line breaks, uppercase, or truncated** (chat apps wrap and mangle text) → whitespace/newlines/case are tolerated; a truncated card gives a clear "card is incomplete or damaged" error, never a panic. Test: Task 2 `TestDecodeCardTolerantInput`, `TestDecodeCardTruncated`.
2. **Adding your own card** → rejected with `contacts.ErrSelf`, nothing stored, no network traffic. Test: Task 6 `TestAddOwnCard`.
3. **Remote peer sends invalid frames** (oversized, invalid UTF-8, wrong ID length, empty text) → the frame is dropped and the stream reset; the app keeps running and later valid messages still arrive. Test: Task 7 `TestHandlerRejectsInvalidFrames`.
4. **Recipient disappears mid-flush** (some messages acked, then the stream dies) → acked ones are `delivered`, the rest stay `pending` and go out on the next flush, and the receiver shows each exactly once. Test: Task 7 `TestFlushInterruptedThenResumed`.
5. **Helper unreachable or no bootstrap configured at startup** → `core.Start` still succeeds quickly (under 2 s), LAN/direct chat still works, and reachability reports "unknown" rather than blocking. Test: Task 8 `TestStartWithUnreachableBootstrap`.

### Task 6: Contacts service

**Files:**
- Create: `internal/contacts/service.go`
- Test: `internal/contacts/service_test.go`

**Interfaces:**
- Consumes: `store.*` (Task 3), `identity.Card` (Task 2), `wire` (Task 1), `event.Bus`, `event.ContactChanged` (Task 4), `p2p.Reacher` (Task 5)
- Produces:
  - `const ProtocolID = "/twocan/contact/1.0.0"`; `var ErrSelf, ErrNotPending`
  - `func New(h host.Host, st *store.Store, r p2p.Reacher, bus *event.Bus, displayName func() string) *Service`; `func (s *Service) Start()` (registers stream handler)
  - `func (s *Service) Add(ctx, c identity.Card) error`; `Accept(ctx, id peer.ID) error`; `Reject(ctx, id peer.ID) error`; `Flush(ctx, id peer.ID) error`
- Protocol: one frame per stream. The initiator sends `Request` or `Accept`; the responder **always** replies `ContactAck`, then the initiator clears `PendingSend`. All state changes publish `ContactChanged`.
- State table:

| Action / frame received | Current state | Result |
| --- | --- | --- |
| `Add(card)` | none or `blocked` | `pending_outgoing`, PendingSend, name/addrs from card; async Flush |
| `Add(card)` | `pending_incoming` | same as `Accept` |
| `Add(card)` | `pending_outgoing`/`accepted` | refresh addrs only |
| `Accept(id)` | `pending_incoming` | `accepted`, PendingSend; async Flush. Other states → `ErrNotPending` |
| `Reject(id)` | any | `blocked`, PendingSend false |
| recv `Request` | none | `pending_incoming` (subject to limits below) |
| recv `Request` | `pending_outgoing` | `accepted`, PendingSend (mutual add) |
| recv `Request` | `accepted` | PendingSend (they lost state; resend Accept) |
| recv `Request` | `pending_incoming`/`blocked` | update name only / nothing |
| recv `Accept` | `pending_outgoing` | `accepted` |
| recv `Accept` | others | nothing |
| `Flush(id)` | PendingSend && `pending_outgoing` → send Request; PendingSend && `accepted` → send Accept; else no-op | on Ack: PendingSend=false |

- Abuse limits: per remote peer, `rate.NewLimiter(rate.Every(12*time.Second), 5)`; more than 100 `pending_incoming` contacts → new requests are acked but dropped. Display names longer than 64 runes are truncated.
